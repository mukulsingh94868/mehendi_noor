# Mehndi Noor

A premium, modern, fully responsive single-page website for a Mehndi / Henna
artist. The website reads service, gallery and published testimonial content
from the Mehndi Noor Express API when configured. The booking form saves
enquiries to that API before opening WhatsApp with a pre-filled message.

## Tech Stack

- Next.js (App Router) + TypeScript
- Tailwind CSS (v3) with shadcn/ui-style components on Radix primitives
- Lucide React icons
- `next/image` + `next/font` (Cormorant Garamond + Inter)

## Getting Started

```bash
npm install
npm run dev      # http://localhost:3000
```

Other scripts:

```bash
npm run build      # production build (fully static / prerendered)
npm run start      # serve the production build
npm run lint       # ESLint (next/core-web-vitals + next/typescript)
npm run typecheck  # tsc --noEmit
```

## Placeholder Content

Everything business-specific is intentionally placeholder and easy to replace:

- **Imagery** — The hero and artist images are local licensed photography in
  `public/images/*.jpg`; services and the gallery use licensed Wikimedia Commons
  photography. Original placeholder artwork remains in `public/images/*.svg`.
  illustrations generated by `scripts/generate-images.mjs`
  (`node scripts/generate-images.mjs`). Swap them for real photography of the
  same filenames and dimensions.
- **Pricing** — `src/data/packages.ts` uses `₹ ____` placeholders only.
- **Testimonials** — `src/data/testimonials.ts` are clearly marked samples.
- **Contact details / socials** — see `CONTACT` in `src/lib/utils.ts` and
  `siteConfig` / `socialLinks` in `src/data/navigation.ts`.
- **SEO URL** — update `metadataBase` in `src/app/layout.tsx`.

## Backend API

Set `NEXT_PUBLIC_API_URL` to the base URL of the Express API (for example
`http://localhost:5000` during local development) in `.env.local`, then restart
the Next.js server. The home page fetches gallery, services, and published
testimonials from `/api/gallery`, `/api/services`, and `/api/testimonials`.
While the API is unavailable, the home page logs the request error and keeps
using its local sample data.

The booking form sends a `POST /api/contact` request first; only after a
successful save does it open WhatsApp with the same submitted details. Failed
API submissions are shown to the visitor and are not reported as successful.
Admin APIs, contact management, content CRUD, and image uploads are documented
in the backend repository README.
